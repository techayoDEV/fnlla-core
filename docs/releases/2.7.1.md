# FNLLA Core 2.7.1

Core 2.7.1 fixes runtime, tenancy and update-recovery boundaries while keeping
existing public interfaces and persisted formats. Availability requires the
matching immutable release and successful CI for its exact source commit.
Core remains standalone, MIT licensed and independent of AI providers.

## Changes

- Reject unknown cache and queue drivers; verify MySQL server certificates when
  TLS is configured unless the application explicitly opts out.
- Restore active actor identity before tenant job execution. Resolve optional
  typed dependencies through the existing scope-aware container.
- Apply body/query/route input precedence, return HTTP 400 for malformed JSON,
  preserve nested route prefixes and negotiate JSON routing errors.
- Reject unsafe cookie directive values; replace response headers without
  case duplicates while preserving multiple cookies.
- Validate every recovery entry before restoring files. Preserve the journal
  on invalid checksums, permissions or restoration failure. Reject private path
  case aliases, transaction metadata, trailing dots and Windows device names.
- Use a filtered existence probe instead of counting all matching database rows.
- Keep optional provider failures degraded with private diagnostic evidence.
- Add explicit bounded-batch cleanup of expired completed file queue receipts.
- Build the existing navigation dependency reproducibly from its pinned package;
  retain native SSR, forms, keyboard behavior and upstream attribution.

## Upgrade and rollback

Install the immutable dependency through Composer. Do not edit vendor or replace
an older release archive. Stop workers during dependency changes and restart
serving processes according to the application's OPcache policy. No database
migration or queue format change is required from 2.7.0.

Unknown driver names now fail instead of falling back to files. Invalid cookie
attributes and update paths now fail before mutation; fix configuration or
payloads rather than disabling validation. For a damaged recovery journal, keep
its private evidence and correct every invalid entry before retrying recovery.
Use the existing transaction lock; do not remove it while writers are active.

`queue:work --prune-completed` is explicit housekeeping, not a scheduler. It
preserves active receipts and scans the directory; measure large stores before
claiming bounded I/O. Existing outbox, snapshot and cache-lock rollout contracts
from 2.7.0 remain applicable. A rollback also restores the corrected defects.

## Verification boundary

Required acceptance includes PHP 8.3/8.4 on Linux and Windows, isolated
MySQL/Redis, upgrade and upload HTTP checks, deterministic cross-platform ZIPs,
a fresh Composer consumer and downstream FNLLA exports. Release assets record
the exact source and CI evidence. These checks do not establish application
RPO/RTO, human usability approval or security certification.

See [runtime contracts](../framework/RUNTIME-CONTRACTS.md) and
[operations](../framework/OPERATIONS.md) for supported behavior and limits.
