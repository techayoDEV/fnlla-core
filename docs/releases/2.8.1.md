# FNLLA Core 2.8.1

Maintenance patch on the frozen Core 2.8 line. Availability requires the matching
immutable release and exact-source CI; a development checkout is not a released
dependency.

## Corrections

Generated applications retain the public documentation index, upgrade notes and
referenced security guides in their bundled Core package. Relative documentation
links are checked in an actual export. Internal release procedures remain omitted.
The starter README identifies Core's MIT notice under
`packages/fnlla-core/LICENSE.md`; application licensing remains the owner's choice.

The maintainer repository has fewer root files: maintenance documents live in
`docs/`, npm inputs in `tools/assets/`, PHPStan configuration in `tools/quality/`
and the Windows convenience launcher in `scripts/windows/`. Use
`npm --prefix tools/assets ci` and `npm --prefix tools/assets run build`.
`composer analyse` and `php fnlla` keep their invocation. Nested npm dependencies
are excluded from Git and both local and stable package inventories.

## Upgrade and operations

Runtime APIs, configuration defaults, database and queue formats, PHP requirements
and dependency pins are unchanged from 2.8.0. No database migration is required.
Existing applications keep their own files and tooling layout; updating a package
does not move application directories. Replace dependencies through the approved
package process and preserve a complete previous package set for rollback.

Core remains usable without Full, a Developer Panel or an AI/search provider.
Keep component notices, trusted deployment configuration and application data.
The [2.8.0 operations and compatibility requirements](2.8.0.md) continue to apply.
