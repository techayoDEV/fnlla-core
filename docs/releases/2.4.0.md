# FNLLA Core 2.4.0

Core 2.4.0 adds developer context, bounded readiness diagnostics, explicit
OpenAPI contracts, optional reliable outbox delivery and concurrency hardening.
PHP remains ^8.3. No AI account, SDK or commercial FNLLA dependency is required.

## Compatibility

- Existing queue, cache and Action store interfaces retain their required
  methods. New capabilities use optional interfaces. Custom adapters can run
  the published `Fnlla\Php\Testing\AdapterContractSuite` checks.
- `runtime:inspect` retains `fnlla.runtime.inspection.v1` and adds `context`
  with schema `fnlla.runtime.context.v1`. Ignore unknown keys in consumers.
- OpenAPI export requires explicit route metadata; it does not infer business
  authorization or request schemas. Readiness probes are bounded and redacted.
- Reliable outbox delivery is disabled by default. Enabling it requires the
  MySQL delivery side table and coordinated publisher restart.
- Redis delayed work uses a new sorted set. Stop every old queue worker before
  upgrading; running mixed versions against the same prefix is unsupported.
- Upload names now use detected MIME bytes; incompatible explicit extensions,
  oversized files and nested symlinks are rejected. Review application upload
  naming and configure matching HTTP deny rules on your deployment server.
- Atomic throttling may reject requests that previously slipped through a
  concurrent read/write race. File cache lock files must remain in place.

## Upgrade from 2.3.1

1. Record the installed package version, manifest and database/queue backups.
   Test application-specific adapters and upload rules against 2.4.0 first.
2. Stop queue workers and outbox publishers. Install the immutable 2.4.0 package
   through Composer and commit the resulting dependency metadata and lock.
3. For reliable outbox, apply `installDeliverySchema()` in an application
   migration outside a transaction. Set `actions.reliable_outbox=true`, rebuild
   config cache and restart all publishers together. Leave it false otherwise.
4. Deploy updated public upload guards. Rebuild route/config caches through the
   application's normal deployment procedure and restart queue workers.
5. Inspect `runtime:inspect`, `runtime:doctor` and `outbox:status` where enabled.
   Verify a real application request, job and event with idempotent handlers.

## Rollback

Stop all workers first. Preserve successful external effects and `published_at`
markers; blindly restoring an old database snapshot can repeat delivered events.
Reconcile reserved and failed work explicitly. Move the delayed sorted-set
members back to the legacy pending-list format before returning to 2.3.1, then
disable reliable outbox and retain its side table until reconciliation is done.
Review every quarantined message: the legacy publisher does not enforce the
new quarantine/backoff policy. Restore the pinned 2.3.1 dependency and rebuild
caches only after that reconciliation.

`scripts/test-upgrade.py` downloads the checksum-pinned, published 2.3.1 artifact
and checks old-format jobs/outbox data, 2.4.0 migration, expired-worker recovery,
delivery and reconciled rollback on isolated MySQL/Redis. It uses synthetic data;
application recovery procedures and external side effects still need their own
rehearsal. Backups in that drill are temporary test evidence, not production RPO/RTO.
