# FNLLA Core 2.7.0

Core 2.7.0 adds optional application snapshots and improves transaction delivery,
diagnostics, cache maintenance and application upgrade preservation. Availability
requires the matching immutable GitHub release and its exact-commit CI evidence.
No Developer Panel, commercial administration or AI provider is included.

## Compatibility and upgrade

- Install the new immutable package through Composer; never patch `vendor/`.
- Transaction callbacks all run after commit. Aggregate private failures preserve
  callback positions. A committed mutation must not be replayed to retry delivery.
- Legacy outbox processing isolates corrupt rows. Existing deployments must opt
  into reliable delivery with the documented migration and supervised workers;
  new starters use reliable delivery. Drain old workers before switching modes.
- File-cache locks use a bounded stripe pool. Stop every old worker before
  changing lock protocols, or explicitly retain `cache.file_lock_protocol=legacy`
  during a coordinated transition. Expiry maintenance preserves live entries.
- Exception reporting is optional and redacted by default. Queue failures use
  allowlisted error codes; historical failed-job records are not rewritten.
- Core-to-Full promotion preserves application-owned delivery configuration.
- Snapshot contracts are optional. They require stopped writers, exclusive
  database ownership, private backups and tested recovery tooling. They do not
  automatically stop services or enable unattended application updates.

See [runtime reliability](../framework/RUNTIME-RELIABILITY.md) and
[application snapshots](../framework/APPLICATION-SNAPSHOTS.md) for rollout,
operational requirements and recovery limits. Normal runtime does not require AI.
